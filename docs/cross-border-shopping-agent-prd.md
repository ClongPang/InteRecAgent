# 跨平台跨境 AI 商品推荐 Agent 产品需求文档

**版本**：1.1
**日期**：2026-08-15
**项目**：InteRecAgent
**文档类型**：产品需求

## 1. 产品概述

### 1.1 产品定位

InteRecAgent 是一个面向中文跨境消费者的、可追踪且可解释的跨平台 AI 商品推荐 Agent。

它将用户的自然语言购物需求转化为可验证的商品约束，利用buywhere提供的数据服务，从多个国际电商平台和国家市场中检索商品，统一换算为人民币进行横向比较，并输出带有事实依据、取舍说明和商户链接的推荐结果。

它并不提供自动代购或自动下单系统，定位仅时帮助潜在用户节省在多跨境电商平台中搜索，查看，比较的时间，是一个“跨平台跨境购物研究员”和“商品购买决策助手”。

提供具体的商品在各平台实际页面的跳转，进行真实的下单购买。

### 1.2 平台聚合与策略

不绑定单一国家或单一平台，而是以 BuyWhere 实际可用的国际平台和国家市场为数据边界，服务以人民币进行决策的中文用户。

原因如下：

- 用户真正需要的是“一次搜索、多个平台比较”，而不是逐个平台打开网页。
- 人民币是目标用户的统一决策货币，但商品价格仍必须保留原币种和汇率信息。
- 首期应选择 2–3 个可稳定调用的市场和平台进行验证，再逐步扩展覆盖范围。

BuyWhere 的公开资料覆盖新加坡、美国及部分东南亚市场，但公开页面的覆盖数量和接口字段存在差异；具体市场应以真实 API Key 的可用结果为准。

“人民币”只表示用户的比较和预算货币，不代表商品一定可以配送到中国大陆。我们项目也不负责实际的购买履约等。

## 2. 背景与问题

### 2.1 用户现状

跨境购物用户通常需要在多个国际平台之间手动搜索、翻译和比价，同时处理不同的币种、商品规格、促销价格、商户信誉、库存状态和售后规则。

传统搜索只能提供商品列表，无法有效回答以下问题：

- 以人民币预算计算，哪个商品最适合？
- 不同平台的商品是否真的是同款？
- 不同国家的价格换算成人民币后，哪个平台更划算？
- 低价是否意味着规格缩水、套装不同或售后较差？
- 当前价格是否值得购买，还是应该等待降价？
- 价格、库存和评分信息是什么时间更新的？

### 2.2 产品机会

BuyWhere 提供面向 AI Agent 的商品目录、结构化规格、商户信息、价格、库存、折扣和比较接口，能够替代 Agent 对网页抓取、页面解析和静态知识的依赖。

BuyWhere 的核心 REST API 为 `https://api.buywhere.ai/v1`。搜索接口支持关键词、平台、区域、国家、价格区间、货币、分页、紧凑响应模式和 `keyword` / `semantic` / `hybrid` 搜索模式；商品结果包含 `structured_specs` 与 `comparison_attributes`，适合进一步进行程序化比较。[BuyWhere 在线 OpenAPI](https://api.buywhere.ai/openapi.json)

## 3. 产品目标与非目标

### 3.1 产品目标

1. 让用户用一句自然语言表达购物需求，并通过少量追问补齐关键约束。
2. 在多个国际平台和市场之间找到满足硬条件的候选商品。
3. 将不同平台的原币种价格换算为人民币，支持统一预算和横向比价。
4. 通过结构化数据完成可解释的商品比较，而不是只返回搜索结果。
5. 为每个推荐结论保留原价、人民币估算价、汇率时间、规格、商户、库存和更新时间等。
6. 在 BuyWhere API 不可用、数据不完整或信息过期时，明确告知用户不确定性。

### 3.2 非目标

- 不负责自动支付、自动下单或代替用户完成交易。
- 不承诺最终运费、关税、清关费用或配送时效；人民币价格默认是商品价换算，不等于跨境到手价。
- 不对商户的真实性、售后质量或保修政策做无依据的保证。
- 不声称“全网最低价”，只能表述为“在当前可检索结果中的较优选择”。
- 不构建自有商品爬虫和完整电商目录。

## 4. 目标用户

### 4.1 主要用户：跨境理性消费者

- **典型特征**：以人民币进行预算管理，会使用中文，熟悉部分电商平台，但没有时间逐个平台比价。
- **目标**：在预算内买到合适、可靠、值得购买的商品。
- **痛点**：国际平台分散、商品规格不统一、跨币种比较困难、汇率波动、低价和真实价值不等价。
- **关键诉求**：人民币价格、原币种和汇率时间、推荐理由、候选差异、价格与库存更新时间、购买链接。

### 4.2 次要用户：高频选品用户

- **典型特征**：经常购买数码、家电或游戏设备，愿意保存偏好和监控价格。
- **目标**：建立个人偏好、关注商品降价和快速复用跨平台搜索条件。
- **关键诉求**：愿望清单、价格历史、人民币目标价、降价提醒和跨市场追踪。

## 5. 核心用户旅程

```text
用户提出购物目标
        ↓
Agent 识别商品、人民币预算、目标市场和硬约束
        ↓
对缺失条件进行最少量追问
        ↓
调用 BuyWhere 搜索候选商品
        ↓
规格归一化、同款识别、硬约束过滤
        ↓
换算人民币并比较价格、评分、库存、更新时间和商户
        ↓
输出首选、备选、取舍理由和购买链接
        ↓
用户继续追问、比较或跳转购买
```

示例：

> 我想买一副适合通勤的降噪耳机，人民币预算不超过 2,500 元，帮我比较Amazon、Shopee和Lazada平台。

Agent 应识别出：商品类别、使用场景、人民币价格上限、目标市场、降噪能力和可购买性，并在必要时追问是否接受翻新机、是否重视续航、品牌、运费或保修。

## 6. 功能需求

### 6.1 自然语言需求理解

系统需要从用户输入中提取：

- 商品类别或具体型号
- 使用场景
- 人民币预算和原始货币
- 目标国家、平台
- 品牌偏好或排除项
- 尺寸、颜色、容量、性能等规格
- 必须满足的硬条件
- 可接受的折中项

**要求：**

- 无法确定商品类别时，Agent 必须追问。
- 预算未提供时，可以先搜索，但应提醒用户结果未按人民币预算约束。
- 用户表达“便宜”“最好”“性价比高”等模糊目标时，系统应转化为可解释的排序策略。
- 用户修改一个约束时，只重新执行受影响的搜索和排序步骤。

### 6.2 BuyWhere 商品搜索

首期使用 `GET /v1/products/search`，按国家或平台分组检索候选商品，主要参数如下：

| 参数 | 用途 |
|---|---|
| `q` | 自然语言或关键词搜索 |
| `domain` | 商户平台过滤，例如 Shopee、Lazada、Amazon |
| `region` | 区域过滤 |
| `country_code` | 目标国家 |
| `min_price` / `max_price` | 对应市场原币种下的价格区间 |
| `currency` | 显式指定市场原币种；不默认传入 CNY |
| `compact` | 获取更适合 Agent 的精简响应 |
| `limit` / `offset` | 分页 |

系统应优先使用 `compact=true` 获取候选集，再按需要获取详情、比较或价格历史。

BuyWhere 的搜索价格过滤发生在目标市场的原币种中。用户输入人民币预算后，系统需要先使用汇率服务估算各市场的原币种预算，再分别调用搜索接口，不能直接假设 BuyWhere 接受人民币预算。

### 6.3 候选商品处理

系统必须在推荐前完成：

- 硬约束过滤
- 商品规格标准化
- 型号、容量、颜色和套装识别
- 同款或近似款区分
- 价格币种确认
- 库存和更新时间检查
- 商户及原始链接保留

不能仅按搜索结果顺序直接把第一项作为推荐。

### 6.4 跨平台人民币比价

系统必须提供统一的人民币展示层，同时保留商品原价。每个价格至少包含：

- 原始价格和原始货币，例如 `USD 299`、`SGD 429`。
- 按指定汇率换算后的人民币估算价，例如 `约 ¥2,149`。
- 汇率来源和更新时间。

人民币换算价的定位是“比较价”，不是最终支付金额。默认展示格式应为“约 ¥X”，而不是伪装成精确人民币售价。

### 6.5 商品比较

用户可以要求比较 2–4 个候选商品。比较维度至少包括：

- 当前原价、人民币估算价和汇率时间
- 品牌与型号
- 关键规格
- 评分和评价数量
- 折扣信息
- 库存状态
- 商户平台
- 数据更新时间

当商品跨越不同货币时，系统不得把 BuyWhere 的静态 `normalized_price_usd` 直接转换成用户最终支付价格。该字段只能作为粗略排序依据；人民币展示必须使用独立汇率服务，并保存汇率快照和时间。[BuyWhere MCP 文档](https://api.buywhere.ai/docs/guides/mcp)

### 6.5 推荐与解释

每次推荐至少包含：

1. 首选商品
2. 推荐理由
3. 关键证据
4. 两个以内的替代方案
5. 主要取舍
6. 原价、人民币估算价和汇率时间
7. 商户和购买链接
8. 价格、库存和信息更新时间

推荐语言示例：

> 推荐 A：满足你的预算和降噪要求，当前价格为 USD 299，按 2026-08-15 汇率约合 ¥2,149，评分 4.8，当前有货。B 的人民币估算价低约 ¥180，但续航和评价数量较弱。汇率、价格和库存会变化，最终金额以商户页面为准。

### 6.6 价格历史与提醒

第二阶段支持：

- 查询商品近 30–90 天价格历史
- 保存商品到愿望清单
- 用户设置目标价格
- 价格下降后发送提醒

价格提醒应采用异步任务，避免每次对话都触发多个 API 请求。

### 6.7 异常处理

系统需要处理：

- API Key 无效：提示服务配置问题，不泄露密钥。
- 参数错误：解释缺失或冲突的搜索条件。
- 无结果：放宽软条件，但不能自动放宽硬条件。
- 429 限流：读取 `Retry-After`，使用指数退避并展示服务降级状态。
- 商品详情不存在：保留搜索结果并标记详情不可用。
- 价格或库存过期：降低可信度，并提示用户在商户页面确认。
- BuyWhere 服务异常：返回已有缓存或明确说明当前无法完成实时检索。
