# 成熟服务版原型规格：持续购物任务

## 目标

将 InteRecAgent 设计为用户可反复进入、持续推进的跨平台选购助手：理解需求，聚合国际商品，统一换算与比较，帮助用户选择后跳转商户。它不承担购买、支付、地址收集、物流或订单服务。

## 会审结论

产品经理、UI 设计师与目标用户一致认为：上一版把“原型、Beta、待接入、待核验”等工程状态直接暴露给用户，虽然谨慎，却不像一个成熟服务。真实服务仍应准确表达商品价、原币、汇率、更新时间和费用边界，但以安静的字段层级呈现，而不是反复声明限制。

## 页面总结构

```text
任务壳（整个任务期间持续存在）
├── 顶部：任务名称 · 候选数 · 已选数 · 当前阶段 · 新建任务
├── 左：Agent 对话轨道
│   ├── 可编辑任务条件：品类 / 预算 / 偏好 / 平台
│   ├── 一次一个关键追问
│   ├── 本轮变化与撤销
│   ├── 可回看的消息记录
│   └── 固定输入框：继续修改这个任务
└── 右：决策工作区
    ├── 候选发现：推荐摘要、筛选、商品卡、候选篮
    ├── 对比决策：同一任务的比较表与推荐变化
    └── 商品详情：右侧抽屉，不中断对话轨道
```

候选与比较是同一任务的两个阶段，不再作为顶级页面。顶栏只保留“新建任务”和“我的任务”；价格关注作为商品或任务的次级动作，功能准备完成后再露出。

## 连续性契约

`ShoppingMission` 是唯一事实源，至少包含：

```text
missionId、标题、阶段、当前约束、约束版本、消息时间线、
检索/汇率/商品证据快照、候选池、已选比较集合、推荐结论、商户跳转记录
```

- 任何输入或快捷操作均追加“任务事件”，不覆盖用户的原始需求。
- 条件变化产生简短可见反馈，例如“预算已更新为 ¥2,000，2 件候选移出预算内”，并可撤销。
- 切换到比较、打开详情、返回候选或刷新页面后，恢复同一任务、对话、候选与比较集合。
- 比较页保留紧凑的对话轨道；用户可以直接追问“更重续航呢”，Agent 只更新相关排序、摘要和高亮。

## 成熟服务微文案

| 场景 | 采用表达 | 不采用表达 |
| --- | --- | --- |
| 首页 | “告诉我需求、预算或想比较的商品。” | “任务，而非搜索框”“没有数据时我会说明” |
| 价格 | `约 ¥2,149` / `USD 299 · 汇率更新于 14:32` | “原型快照”“不等于最终到手价” |
| 费用 | `费用：结算页显示`，仅在详情或比较中出现 | 每张卡反复写“待确认/未知” |
| 推荐 | “降噪、续航和评价更均衡。” | “费用未参与评分” |
| 无结果 | “未找到符合当前条件的商品。”并提供调整条件 | “等待真实搜索接入”“不会展示虚构结果” |
| 跳转 | `前往 Amazon 查看`，辅助文字“将在 Amazon 完成结算” | 强制勾选“我会在商户页核验” |

必要的边界不消失，而是归位：商品卡保留原币与人民币估算，详情/比较提供更新时间和“费用：结算页显示”，商户跳转处只提示一次“价格和费用以商户页面为准”。配送相关信息不属于当前产品的展示或服务范围。

## 开发验收

1. 任务在刷新、返回“我的任务”、候选、比较与详情之间保持一致。
2. 比较页可继续对话；调整偏好后，比较集合不丢失，推荐依据同步更新。
3. 每项条件变更都有可理解的影响反馈与撤销入口。
4. 每件商品展示平台、原币、人民币估算、更新时间和关键规格；真实 BuyWhere URL 用于商户跳转。
5. 不出现“原型”“Beta”“等待接入”“未实现”等开发期文案。
6. 不出现支付、购物车、代购、地址收集、物流承诺或订单管理。
